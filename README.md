# Lizon

Современная LMS: курсы из модулей и активностей, банк вопросов с плагинами, кабинеты студента, преподавателя и администратора. Один человек может иметь несколько ролей.

## Стек

- **Веб:** Next.js 15, React 19, TypeScript. Кабинеты — клиентские страницы, запросы идут на `/backend`, Next проксирует их на API, поэтому cookie сессии остаются на том же origin.
- **API:** NestJS 11, REST, Zod на входе. Общий префикс `/api`.
- **Данные:** PostgreSQL 16 и Prisma. Redis 7 для лимитов запросов; если Redis недоступен, счётчик живёт в памяти процесса.
- **Файлы:** локальный диск или S3-совместимое хранилище (`STORAGE_DRIVER=s3`, подходит MinIO).
- **Вопросы:** пакет `@lizon/shared`. Проверка ответов одна и та же на API и в тестах, формулы считаются своим разбором без `eval`.

Nest выбран вместо «всё в Next», потому что попытки, банк и права — долгие серверные сценарии со своей схемой и очередью проверки. Общий пакет не даёт фронту и API разъехаться в правилах оценивания.

## Что уже работает

- Роли `student`, `teacher`, `methodist`, `admin` и свои роли. Права складываются. Роль на курсе (студент / преподаватель / ассистент) отдельно от глобальной.
- Курс → модуль → активность: урок, тест, задание, форум, ресурс, интерактив. Версии материалов, условный доступ (дата, завершение, оценка, группа), прогресс.
- Банк вопросов и типы: множественный выбор, верно/неверно, короткий и числовой ответ, эссе, соответствие, три drag-and-drop, порядок, описание, Cloze, вычисляемый и вычисляемый с выбором, hotspot, пропущенные слова, плюс пример плагина `scale`.
- Случайный слот, попытки, таймер, перемешивание, режимы обратной связи, штраф, частичные баллы, ручная проверка.
- Импорт и экспорт JSON (`lizon-questions-v1`) и Moodle XML. В банке файл загружается целиком в выбранную категорию (`POST /api/questions/import`). Поддерживаются multichoice, truefalse, shortanswer, numerical, essay, matching, description, cloze, calculated и calculatedmulti. Неизвестный тип пропускается с предупреждением.
- Задания с файлом, обсуждения, карточки и простые симуляции внутри урока, сертификат PDF после прохождения и проверки.
- Светлая и тёмная тема, акцент в профиле, русский и английский, уведомления в кабинете и по почте (если задан `SMTP_HOST`, иначе письмо пишется в лог).
- Вход по почте и паролю. Google OAuth включается переменными `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.

## Локальный запуск

Нужны Node.js 22, PostgreSQL 16 и, по желанию, Redis.

```bash
cp apps/api/.env.example apps/api/.env
# создайте пользователя и базу lizon/lizon, строка подключения уже в примере
npm ci
npm run build -w @lizon/shared
npm run db:generate -w @lizon/api
npm run db:migrate -w @lizon/api
npm run db:seed -w @lizon/api
npm run dev -w @lizon/api
npm run dev -w @lizon/web
```

Веб: http://localhost:3000. API: http://localhost:4000/api/health.

Повторный сид заново создаёт курс `data-literacy` и стирает попытки по нему.

## Docker Compose

```bash
docker compose up --build
```

Демо-курс создаётся отдельно и при повторе перезаписывает курс со слагом `data-literacy`:

```bash
docker compose run --rm --entrypoint npx api tsx src/seed.ts
```

`SEED_ON_BOOT=true` делает то же самое при каждом старте API. Для обычной работы оставьте `false`, иначе перезапуск контейнера сотрёт попытки демо-курса.

Секреты в compose — учебные. Перед публикацией смените `JWT_ACCESS_SECRET` и `JWT_REFRESH_SECRET`, поставьте `COOKIE_SECURE=true` за HTTPS.

## Тесты

```bash
npm test
```

Сначала пакет вопросов (формулы, все типы, импорт Moodle XML), затем API: политика ролей и сквозной сценарий «студент сдаёт тест, преподаватель ставит балл за эссе». Интеграционный тест собирает Nest в `dist`: Vitest не сохраняет метаданные декораторов.

## Как добавить тип вопроса

Реализуйте `QuestionPlugin` (`validate`, `emptyDefinition`, `materialize`, `publicView`, `grade`, `solution`) и вызовите `registerQuestionPlugin` при старте API. Образец — `apps/api/src/plugins/scale.ts`. Ядро попытки тип не знает: оно просит плагин собрать попытку и проверить ответ.

Схема данных и границы модулей — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
